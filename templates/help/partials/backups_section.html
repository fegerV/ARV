backup {{ "Backups and restore" if is_en else "Резервные копии и восстановление" }}

{% if is_en %}Backups protect the platform from data loss. Copies are managed in /backups and in Settings -> Backups, and are stored outside the server on Yandex Disk.{% else %}Резервные копии защищают платформу от потери данных. Копии создаются и настраиваются в разделах /backups и Настройки → Бэкапы, а хранятся вне сервера — на Яндекс Диске.{% endif %}

{{ "1. What gets backed up" if is_en else "1. Что попадает в копии" }}

  • {% if is_en %}Database — tables, settings, companies, projects and AR content. The dump is compressed and then encrypted.{% else %}База данных — таблицы, настройки, компании, проекты и AR-контент. Дамп сжимается и затем шифруется.{% endif %}
  • {% if is_en %}Media — original images and videos, stored as a restic snapshot.{% else %}Медиа — оригиналы изображений и видео, хранятся снапшотом restic.{% endif %}
  • {% if is_en %}Secrets — the environment file and TLS material, as a separate encrypted archive.{% else %}Секреты — файл окружения и TLS-материалы, отдельным зашифрованным архивом.{% endif %}

{{ "2. Automatic backups" if is_en else "2. Автоматическое создание" }}

{% if is_en %}Configured once in Settings -> Backups:{% else %}Настраивается один раз в разделе Настройки → Бэкапы:{% endif %}

  • {% if is_en %}enable backups with the switch at the top of the tab;{% else %}включите бэкапы переключателем в начале вкладки;{% endif %}
  • {% if is_en %}pick the company whose Yandex Disk receives the copies;{% else %}выберите компанию, на Яндекс Диск которой будут складываться копии;{% endif %}
  • {% if is_en %}set the destination folder (default backups);{% else %}укажите папку назначения (по умолчанию backups);{% endif %}
  • {% if is_en %}choose the schedule — daily, twice a day, weekly, or your own cron expression (default 0 3 * * *, i.e. 03:00 server time);{% else %}выберите расписание — ежедневно, дважды в день, еженедельно или свой cron (по умолчанию 0 3 * * *, то есть 03:00 по времени сервера);{% endif %}
  • {% if is_en %}set retention — how many daily, weekly, monthly and yearly copies to keep;{% else %}задайте срок хранения — сколько дневных, недельных, месячных и годовых копий хранить;{% endif %}
  • {% if is_en %}save. The schedule is re-registered immediately, no restart needed.{% else %}сохраните. Расписание перерегистрируется сразу, перезапуск не нужен.{% endif %}

{{ "3. Creating a copy manually" if is_en else "3. Создание копии вручную" }}

  1. {% if is_en %}Open /backups and press Create backup — or press Run now on the Backups tab of the settings page.{% else %}Откройте /backups и нажмите Создать бэкап — либо кнопку Запустить сейчас на вкладке «Бэкапы» в настройках.{% endif %}
  2. {% if is_en %}The copy is made in the background: the button reports that it has started, and the page can be refreshed in a minute.{% else %}Копия создаётся в фоне: кнопка сообщит о запуске, страницу можно обновить через минуту.{% endif %}
  3. {% if is_en %}A new row appears in the run history with the date, type, status, size, trigger and storage path.{% else %}В истории запусков появится строка с датой, типом, статусом, размером, источником и путём в хранилище.{% endif %}

{% if is_en %}Manual runs are for a copy before a risky change, not a replacement for the schedule.{% else %}Ручной запуск нужен для копии перед рискованным изменением, а не вместо расписания.{% endif %}

{{ "4. Checking that a copy is usable" if is_en else "4. Проверка, что копия пригодна" }}

  • {% if is_en %}A copy is only useful if it actually restores, so a green status is not enough on its own.{% else %}Копия полезна только тогда, когда из неё действительно можно восстановиться, поэтому зелёного статуса самого по себе недостаточно.{% endif %}
  • {% if is_en %}Check the status and a non-zero size in the history table.{% else %}Проверьте статус и ненулевой размер в таблице истории.{% endif %}
  • {% if is_en %}Database and secrets artifacts can be downloaded from the row — they are stored encrypted, so they are decrypted where the key lives.{% else %}Артефакты БД и секретов можно скачать из строки — они хранятся зашифрованными, поэтому расшифровываются там, где лежит ключ.{% endif %}
  • {% if is_en %}Media copies are restic snapshots: they are not a single downloadable file and are checked with restic.{% else %}Медиа-копии — это снапшоты restic: файлом они не скачиваются и проверяются средствами restic.{% endif %}

{{ "5. Restoring from a copy" if is_en else "5. Восстановление из копии" }}

{% if is_en %}There is deliberately no restore button in the interface: restoring over the live database is irreversible, so the switch is a separate, conscious step taken from the command line.{% else %}Кнопки «восстановить» в интерфейсе намеренно нет: восстановление поверх рабочей базы необратимо, поэтому переключение — отдельный осознанный шаг из командной строки.{% endif %}

{% if is_en %}Always restore into a separate database first and check the data there.{% else %}Сначала всегда восстанавливайте в отдельную базу и проверяйте данные там.{% endif %}

{% if is_en %}Rehearsal, safe for production:{% else %}Проверочное восстановление, прод не затрагивается:{% endif %}

cd /opt/arv/app && set -a; . ./.env; set +a
/opt/arv/venv/bin/python -m app.cli.backup restore <id> \
    --target-db vertex_ar_recovered --create-db
sudo -u postgres psql -d vertex_ar_recovered -tAc "SELECT count(*) FROM ar_content"
sudo -u postgres psql -tAc "DROP DATABASE vertex_ar_recovered"

{% if is_en %}When the database is already gone, go through a file: the normal path resolves the storage token from that database, so it cannot be the way back from losing it.{% else %}Если база уже потеряна — идите через файл: обычный путь берёт токен хранилища из самой базы, поэтому он не может быть способом вернуться после её потери.{% endif %}

/opt/arv/venv/bin/python -m app.cli.backup download <id> \
    -o /var/backups/arv/backup.sql.gz.age
/opt/arv/venv/bin/python -m app.cli.backup restore \
    --from-file /var/backups/arv/backup.sql.gz.age \
    --target-db vertex_ar_recovered --create-db
  • {% if is_en %}Switch the application to the restored database only after the contents have been verified — it is a separate step, not part of the restore.{% else %}Переключайте приложение на восстановленную базу только после проверки содержимого — это отдельный шаг, а не часть восстановления.{% endif %}
  • {% if is_en %}An encrypted copy needs the private key; it is kept off the server on purpose, so bring it in for the restore window and remove it afterwards.{% else %}Для зашифрованной копии нужен приватный ключ; он намеренно хранится вне сервера, поэтому его приносят на время восстановления и убирают после.{% endif %}
  • {% if is_en %}After a restore, check that the number of tables and a few known records match what you expect.{% else %}После восстановления сверьте число таблиц и несколько известных записей с ожидаемым.{% endif %}
{% else %}

{% if is_en %}Restore is performed by the platform administrator from the server — there is no restore button in the interface, because restoring over the live database is irreversible. Contact your administrator if you need a copy restored.{% else %}Восстановление выполняет администратор платформы с сервера — кнопки восстановления в интерфейсе нет, так как восстановление поверх рабочей базы необратимо. Если нужно восстановить копию, обратитесь к администратору.{% endif %}

{{ "Important details" if is_en else "Важные детали" }}

  • {% if is_en %}Database copies are encrypted, and the private key does not live on the server. That is why an automatic check there confirms only older unencrypted copies — a real restore test is done by the administrator with the key temporarily in place.{% else %}Копии базы шифруются, а приватный ключ на сервере не хранится. Поэтому автоматическая проверка на сервере подтверждает только старые незашифрованные копии, а настоящую проверку восстановления делает администратор, временно положив ключ.{% endif %}
  • {% if is_en %}Retention deletes the history row together with the copy, so record ids are not permanent — refer to a copy by its date and type.{% else %}Ротация удаляет запись из истории вместе с самой копией, поэтому id записей непостоянны — ссылайтесь на копию по дате и типу.{% endif %}
  • {% if is_en %}The off-site copy lives on Yandex Disk only; there is no second storage location yet.{% else %}Внешняя копия существует только на Яндекс Диске; второго места хранения пока нет.{% endif %}
  • {% if is_en %}Deleting a copy from the interface removes it from storage and cannot be undone.{% else %}Удаление копии из интерфейса убирает её из хранилища и не отменяется.{% endif %}
  • {% if is_en %}After enabling the schedule, confirm that the first run really appeared in the history.{% else %}После включения расписания убедитесь, что первый запуск действительно появился в истории.{% endif %}
